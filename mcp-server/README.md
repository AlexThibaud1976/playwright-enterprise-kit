# PEK MCP Server

MCP (Model Context Protocol) server for the **Playwright Enterprise Kit**. It exposes the kit's CI/CD workflows as tools that any MCP client (Claude Code, Claude Desktop, ...) can call in natural language:

> "Run the smoke tests on Chrome latest / Windows 11 via BrowserStack, upload the results to Xray under Test Plan PROJ-100 and update the Confluence dashboard."

## Tools

| Tool | What it does | Underlying kit logic |
|---|---|---|
| `pek_run_tests` | Runs `npx playwright test` (grep, project, config, headed, extra env), returns exit code + pass/fail summary | `package.json` scripts |
| `pek_get_last_run_summary` | Lists last-run artefacts (`xray-report.xml`, `playwright-report/`, `test-results/`) with timestamps | filesystem |
| `pek_resolve_browserstack_config` | Validates an OS/browser combo against the BrowserStack API and returns `BS_*` env vars | `scripts/resolve-browserstack-config.js` |
| `pek_get_browserstack_build_link` | Finds the Automate dashboard URL for a build name | `scripts/get-browserstack-build-link.js` |
| `pek_upload_to_xray` | Uploads JUnit results to Xray Cloud, returns the created Test Execution key | TypeScript port of `scripts/upload-xray.ps1` (cross-platform, no PowerShell needed) + `scripts/remove-test-keys.js` |
| `pek_update_confluence_report` | Appends an execution row to the Confluence "Test Execution Dashboard" | `scripts/update-confluence-report.js` |

Design principle: wherever a kit script is already Node, the tool **wraps** it (single source of truth). Only the PowerShell Xray upload was ported to TypeScript so the server runs identically on Windows, macOS and Linux.

## Install & build

```bash
cd mcp-server
npm install
npm run build
```

## Configure your MCP client

### Claude Code (`.mcp.json` at the repo root, or `claude mcp add`)

```json
{
  "mcpServers": {
    "playwright-kit": {
      "command": "node",
      "args": ["mcp-server/dist/index.js"],
      "env": {
        "BROWSERSTACK_USERNAME": "...",
        "BROWSERSTACK_ACCESS_KEY": "...",
        "XRAY_CLIENT_ID": "...",
        "XRAY_CLIENT_SECRET": "...",
        "JIRA_PROJECT_KEY": "MYPROJECT",
        "JIRA_URL": "https://yourco.atlassian.net",
        "CONFLUENCE_URL": "https://yourco.atlassian.net/wiki",
        "CONFLUENCE_USER": "you@yourco.com",
        "CONFLUENCE_API_TOKEN": "...",
        "CONFLUENCE_SPACE_KEY": "QA"
      }
    }
  }
}
```

### Claude Desktop (`claude_desktop_config.json`)

Same block, but use an **absolute path** in `args` and add `"PEK_ROOT": "/absolute/path/to/playwright-enterprise-kit"` to `env` (the server otherwise assumes it lives in `<kit>/mcp-server/`).

> Secrets stay in the MCP client config or your shell environment — they are read by the server process and are never exposed to the model.

## Environment variables

| Variable | Used by | Required |
|---|---|---|
| `PEK_ROOT` | all tools | No (defaults to the parent of `mcp-server/`) |
| `BROWSERSTACK_USERNAME` / `BROWSERSTACK_ACCESS_KEY` | BrowserStack tools, BrowserStack runs | For BrowserStack features |
| `XRAY_CLIENT_ID` / `XRAY_CLIENT_SECRET` | `pek_upload_to_xray` | Yes for Xray upload |
| `XRAY_ENDPOINT` | `pek_upload_to_xray` | No (default `xray.cloud.getxray.app`) |
| `JIRA_PROJECT_KEY` | `pek_upload_to_xray` | If `projectKey` arg omitted |
| `JIRA_URL` | Confluence dashboard links | No |
| `CONFLUENCE_URL` / `CONFLUENCE_USER` / `CONFLUENCE_API_TOKEN` / `CONFLUENCE_SPACE_KEY` | `pek_update_confluence_report` | Yes for Confluence updates |

## Typical chained workflow

1. `pek_resolve_browserstack_config` → get `BS_*` variables
2. `pek_run_tests` with `config="playwright.config.browserstack.js"` and the `BS_*` values as `extraEnv`
3. `pek_upload_to_xray` → get the Test Execution key
4. `pek_get_browserstack_build_link` → get the build URL
5. `pek_update_confluence_report` with the exec key + build URL

## Notes & limits (v0.1.0)

- `pek_run_tests` is synchronous: it waits for the run to finish (configurable `timeoutSeconds`, default 900s). An async `run_id` / `get_run_status` pattern is a candidate for v0.2 for very long campaigns.
- Reporters from `playwright.config` are not overridden, so `xray-report.xml` keeps being generated by `@xray-app/playwright-junit-reporter`.
- `pek_upload_to_xray` and `pek_update_confluence_report` create/modify remote resources (Jira Test Execution, Confluence page) on every call.
